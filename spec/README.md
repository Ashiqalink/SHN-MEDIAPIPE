# Shared behavior fixtures v1

All paths are relative to `pixorra/`. Fixtures are backend-neutral UTF-8 JSON;
no Python object pickles, absolute paths, or host exception text. Each case file
is `{fixtureVersion: 1, area, cases: [...]}`. Each case has a unique `id`, `input`
object, and exact `expect` object. Optional `phase` identifies the first backend
phase required to execute it. Unknown fields in this envelope are errors.

| Area / directory | Input | Expected result |
|---|---|---|
| `schema` | schema file or JSON plus mutations, bound source files, optional config/history | ordered diagnostic codes/locations, schema identity, loaded entities/references |
| `expressions` | expression, mode, declared context types/values, declared flags/values, optional seed/stream | boolean or unknown reasons or error code; draws consumed and final RNG state |
| `lint` | schema path, map of relative paths to raw file text, disabled rules | complete report from the model contract, including counts, unknowns and disabled rules |
| `simulation` | schema, files, initial counts/flags/stages/context, seed/stream strings, ticks, optional branch snapshot | ordered tick records, changes, evaluations, state and RNG before/after |
| `roundtrip` | source filename, edit pointer/value or insert/delete operation | no-op byte equality; edited bytes or exact patch spans and untouched byte checks |
| `save` | source bytes/hash, edits, session/preview state, injected disk revisions or I/O faults | preview/conflict/status, resulting bytes, remaining dirty files and temp-file cleanup |
| `rng` | algorithm, seed/stream strings, draw count | fixed-width lowercase hex output words; exact decimal state/increment strings |

Decimal content values are JSON numbers; seeds and unsigned 64-bit RNG state are
strings. Compare numbers exactly, never through binary float. Expected reports
compare every key and array order; diagnostic messages may not be ignored once
a rule-specific golden report is present. Missing expected fields are not wildcards.
Raw byte fixtures live beside their manifest; do not normalize newline, BOM,
escape or numeric spelling. Expected outputs must not be generated by the backend
under test. Schema fixtures are game schemas and follow the supported profile.

`fixtures/acceptance.json` records the phase 0 exit acceptance matrix and future
runtime obligations. Its `expect` objects are acceptance assertions, not claims
that future implementations already pass. `fixtures/rng/pcg32.json` is a golden
algorithm vector. Phase 1 adds executable schema/project tests; phases 2, 4, and
6 add byte-edit, complete lint/expression, and simulation fixture executors.

Run available headless checks from this directory's parent:

```text
python -m unittest discover -s tests -v
```

Every later backend must execute the same applicable fixtures unchanged. Behavior
changes update contracts and fixtures in the same change. Cross-platform CI runs
the whole applicable suite on each commit once CI is established in phase 6.
Recording a later-phase case does not complete that phase or its success metric.

Phase 1 `schema/loading.json` cases use the falling-sand example as the base.
`input.schemaEdits` and `input.contentEdits` are arrays of `{pointer, value}`
assignments applied in order to schema or content. A final missing object member
may be added; intermediate pointer segments must exist. `expect.raises` records
whether editable schema loading is refused; `expect.codes` is the exact sorted
diagnostic code sequence, including informational messages. Optional
`expect.materials` is the exact material ID sequence in source order.

Phase 2 executes all `roundtrip/cases.json` byte seeds with no-op equality and
one-edit offset/span checks. Additional container insertion/deletion, Unicode,
exact decimals and mixed local styles are covered by `tests/test_phase2.py`.

`lint/mvp.json` reuses the schema/content mutation format against the falling-sand
sample. The executor writes JSON with two spaces, literal UTF-8 and LF on every
host; expected schema hashes and byte spans therefore stay portable. Each
`expect` is the complete report, including exact diagnostics and counts. Eleven
golden cases cover passing/failing rules, L-5 external unknowns and item overrides,
and disabled rules. Expected reports were authored independently of the backend.

`save/mvp.json` starts each case in a fresh copy of the sample and a new session.
`mutation: true` sets the first material density to 3. `acknowledge: true`
simulates explicit approval of the prepared token. `fault` selects an injected
conflict, replace, file-fsync or directory-sync failure. `expect` compares the
exact batch status, preview requirement, disk state (original/candidate/external),
history existence, temporary-file count and per-file statuses. Additional tests
exercise exact-hash overrides, reload, final-check races, partial batches,
schema/history acknowledgment and failures after content replacement.
